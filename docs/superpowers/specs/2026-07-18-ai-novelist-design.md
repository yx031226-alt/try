# AI 智能小说家产品需求与系统设计

> 文档版本：1.0  
> 日期：2026-07-18  
> 产品阶段：个人本地版 MVP  
> 后续方向：商业化 SaaS  
> 设计状态：已完成方案评审，待书面确认

## 1. 文档目的

本文定义“AI 智能小说家”个人本地版的产品范围、系统架构、核心数据、Skill 边界、交互流程、非功能要求、验收标准和版本路线，作为后续技术设计、任务拆解和验收的唯一产品基线。

## 2. 产品定义

AI 智能小说家不是单纯的文本生成器，而是一个面向个人网络小说作者的人机共创系统。系统以“创作记忆”为核心大脑，以“人物关系与伏笔管理”为质量控制核心，通过八个创作流程 Skill 完成从选题到复盘的完整闭环。

首版采用本地桌面应用形态，作者掌握所有核心创作决策。AI 负责分析、提案、生成、校验、追踪和复盘，不得未经批准静默修改正式设定。

### 2.1 产品目标

MVP 应支持作者完成一卷约 30–50 章、总计不超过 30 万字的创作，并做到：

- 每章创作前自动加载相关记忆并执行一致性检查。
- 每章批准后自动更新剧情、人物、关系、伏笔与素材状态。
- 核心设定修改必须先做影响分析并保留版本记录。
- 人物状态、知情范围、物品归属和作品时间线可按章节回放。
- 短、中、长线伏笔可以登记、推进、预警、回收和复盘。
- 支持多个模型提供商，作品数据不绑定任何单一模型。

### 2.2 核心用户

- 首版：单人创作的网络小说作者。
- 后续：需要多作者协作、权限、计费和云同步的商业 SaaS 用户。

### 2.3 核心痛点

1. 长篇创作后遗忘前文，设定互相冲突。
2. 人物位置、伤势、能力、物品和认知状态无故重置。
3. 人物关系跳变，冲突与爽点缺少铺垫。
4. 伏笔只挖不填，回收时机与证据链不合理。
5. 桥段、反转、意象、句式和章节钩子重复。
6. AI 未经确认擅自新增或修改核心事实。

### 2.4 非目标

MVP 不包含：

- 多作者实时协作、团队权限与批注。
- 登录、订阅、计费与模型额度销售。
- 小说网站自动发布。
- 移动端原生应用。
- 无人值守生成整本小说。
- 专属模型训练或微调。
- 全网抄袭检测与复杂版权判断。

## 3. 产品原则

1. **作者最终决策**：AI 的所有正式数据变更均为提案，须由作者批准。
2. **事件先于状态**：正式变化先写入事件账本，再计算当前状态。
3. **结构化事实优先**：模型推测不得覆盖已批准的结构化事实。
4. **最小必要上下文**：按任务加载相关记忆，不把整部作品无差别提交给模型。
5. **风险分级**：问题分为阻断、警告和建议，允许作者有理由破例。
6. **可追溯、可恢复**：任一正式内容均可追溯来源、版本、批准人与影响范围。
7. **协议稳定、实现可换**：Skill、模型和存储通过稳定协议解耦，为 SaaS 迁移留出空间。

## 4. 术语与模块数量

- **创作记忆**：底层系统能力和事实中心，不计入业务 Skill 数量。
- **核心 Skill**：人物关系与伏笔管理，由关系引擎和伏笔引擎组成。
- **八个流程 Skill**：通用写作规范、选题、世界观、人物、大纲、正文、润色、复盘。
- **业务 Skill 总数**：九个，即一个核心 Skill 加八个流程 Skill。
- **正式数据**：通过校验并由作者批准、已经写入事件账本的数据。
- **提案**：AI 或作者尚未批准的候选变更，不影响正式状态。

## 5. 总体架构

### 5.1 六层架构

1. **交互层**：作品管理、流程向导、正文编辑、关系图谱、伏笔看板、告警和版本对比。
2. **创作编排层**：控制准备、生成、校验、确认和入账流程；阻止 Skill 绕过审批直接写库。
3. **Skill 层**：承载九个业务 Skill，每个 Skill 有独立输入、输出、版本、依赖和校验清单。
4. **创作记忆层**：负责事实检索、状态计算、上下文组装、一致性校验、版本和影响分析。
5. **模型适配层**：以统一协议连接不同模型提供商，根据能力标签选择模型。
6. **数据层**：事件账本、SQLite 实时视图、正文文件及 Markdown/YAML 快照。

### 5.2 数据真相层级

- 事件账本是唯一事实来源，正式事件只追加，不原地覆盖。
- SQLite 实时表是由事件计算出的当前视图，可重建。
- Markdown/YAML 是可读快照、交换与备份格式，不作为并行事实源。
- 正文按卷、章独立保存，并记录对应的事件批次和记忆版本。

### 5.3 标准状态机

所有创作产物统一经过：

`草案 → 待校验 → 待作者确认 → 已批准 → 已入账 → 已生成快照`

异常分支包括：

- 校验失败：回到草案或进入待修复。
- 作者拒绝：进入已拒绝，不改变正式状态。
- 暂不决定：进入待处理提案。
- 有意破例：登记理由、范围、期限后进入批准流程。

### 5.4 章节创作闭环

1. 作者确认本章目标与章纲。
2. 系统按人物、地点、剧情线和伏笔生成最小上下文包。
3. 执行设定、状态、关系、伏笔、素材和禁忌的创作前校验。
4. 正文 Skill 生成草稿及结构化“本章变化清单”。
5. 系统对正文、变化清单和正式记忆交叉校验。
6. 作者修改并批准正文及变更提案。
7. 正文、事件批次和状态更新在同一事务中完成。
8. 生成快照、复盘输入与下一章继承约束。

## 6. 创作记忆核心大脑

### 6.1 设定字典

统一保存世界、人物与关系事实。每条记录包含：

- 唯一编号、标准名称、别名、类型和所属层级。
- 正式描述、关键词、生效章节和失效章节。
- 信息等级：核心事实、普通事实、传闻、谎言、未知。
- 可见范围：作者、读者及具体人物的知情状态。
- 硬度等级：S、A、B、C。
- 来源、版本、修改原因及关联对象。

硬度定义：

- S：作品基石，修改必须执行全局影响分析和二次确认。
- A：重要设定，修改必须执行影响分析并确认。
- B：普通正式设定，按标准审批流程修改。
- C：临时假设，可补全或撤销，但仍保留历史。

客观真相与人物认知必须分开存储。

### 6.2 剧情进度台账

每章批准后更新：

- 章节目标、事件、结果、时间、地点和出场人物。
- 冲突、爽点、转折及章节钩子。
- 新增或变更设定。
- 人物、关系、物品、资源和任务状态变化。
- 伏笔埋设、强化、误导、揭示和回收。
- 下一章必须继承的约束。
- 实际剧情与原大纲的偏差及批准记录。

系统同时维护作品内时间线与章节叙事顺序，以支持插叙、倒叙和多线并行。

### 6.3 人物实时状态表

保存指定章节结束时的人物状态：

- 生死、位置和所处时间。
- 身体、伤势、情绪和精神状态。
- 能力、等级、限制、冷却与代价。
- 物品、资源、债务和任务。
- 已知信息、误解、秘密和目标。
- 对其他人物的态度、信任及关系认知。
- 当前危机、短期动机和长期欲望。
- 最近一次变化的事件来源。

### 6.4 伏笔状态表

标准生命周期：

`构思 → 已埋设 → 已强化 → 部分揭示 → 已回收 → 已验证`

辅助状态：

`待补铺垫 / 临近到期 / 已逾期 / 已改线 / 已废弃`

每条伏笔包含：等级、真实答案、读者可见信息、证据、误导线索、关联对象、预计回收窗口、回收条件、状态、完成度和实际回收效果。

### 6.5 已用素材库

记录剧情桥段、冲突结构、爽点、反转、场景、意象、比喻、动作描写、人物口头禅、金句、对话套路、章节开头、结尾、悬念类型及命名构词。

系统根据使用次数、最近使用章节、重要程度和相似度提示重复。素材并非永久禁用，作者可批准有意复现、主题呼应或变体使用。

### 6.6 全局禁忌清单

禁忌分为：

- 内容禁忌。
- 设定禁忌。
- 写法禁忌。
- 平台禁忌。

每条记录包含适用范围、严重等级、反例、允许例外和例外批准记录。阻断级禁忌由所有 Skill 强制执行。

### 6.7 上下文组装

系统根据当前任务生成上下文包，优先级依次为：

1. 全局禁忌和 S/A 级硬设定。
2. 本章直接相关人物的实时状态与认知。
3. 当前关系、冲突、铺垫和伏笔任务。
4. 本章大纲、上章衔接和下一步约束。
5. 相关历史摘要和已用素材。
6. 语义检索得到的补充内容。

每类上下文设置数量或长度预算；被省略内容必须可以查看。

### 6.8 版本与影响分析

核心设定修改采用提案制：

1. 提出修改及原因。
2. 列出受影响章节、人物、关系、伏笔和大纲节点。
3. 作者选择从当前章节生效、追溯修改或增加解释性例外。
4. 创建新版本，不删除旧版本。
5. 将受影响内容加入待复核队列。

任一章节均可还原其创作时使用的记忆状态。

## 7. 人物关系与伏笔管理核心 Skill

### 7.1 人物关系四级分层

| 等级 | 定义 | 强制要求 |
|---|---|---|
| 核心 | 直接驱动主线和人物弧光 | 绑定主冲突、核心爽点和阶段转折 |
| 紧密 | 高频互动并影响重要选择 | 绑定利益、情感或立场牵引 |
| 关联 | 在支线、组织或阶段剧情产生影响 | 记录作用范围和退出条件 |
| 工具 | 承担传信、引路、交易等功能 | 控制篇幅，避免无依据抢占主线 |

关系可以升降级，但必须有事件依据。

### 7.2 关系数据

关系允许双向不对称，记录：

- 公开身份与真实关系。
- 信任、情感、利益依赖和权力差。
- 立场一致度与秘密掌握程度。
- 当前冲突、潜在冲突和不可调和矛盾。
- 双方各自的关系认知。
- 关系表象与真实状态。
- 开始、结束和转折条件。

### 7.3 冲突与爽点绑定

每段核心或紧密关系至少绑定：

- 一个持续性矛盾。
- 一个阶段性冲突。
- 一个读者期待的关系爽点。
- 一个恶化或升级条件。
- 一个可用于铺垫的行为信号。

### 7.4 关系演变台账

标准演变链：

`初识 → 接触 → 建立判断 → 试探 → 变化积累 → 临界事件 → 关系转变 → 新状态稳定`

每次转变记录触发事件、前置铺垫、双方认知变化、表面与真实变化、后续行为影响和爽点兑现情况。缺少铺垫时标记为关系跳变并阻断确认；作者可登记“刻意异常”及后续解释任务后破例。

### 7.5 伏笔分级标准

#### 短线伏笔

- 原则上 10 章内回收。
- 服务局部悬念、反转或阶段冲突。
- 在预计回收窗口前 2 章开始预警。
- 每 2–3 章至少设置一个有效章节钩子。

章节钩子与伏笔独立登记：钩子负责推动阅读，伏笔负责因果兑现，两者可以重合。

#### 中线伏笔

- 原则上在当前卷内回收。
- 每卷维持 3–5 个承担高潮或反转作用的中线伏笔。
- 回收前至少经历一次强化或变体提示。
- 卷末未回收时必须选择延期、改线或废弃并填写原因。

#### 长线伏笔

- 贯穿多卷或全书。
- 全书建议维持 3–5 个终极真相。
- 每卷至少有一次可感知推进。
- 回收前检查早期证据是否充分及是否存在逻辑反证。

### 7.6 伏笔预警

- 蓝色：正常推进。
- 黄色：进入预期处理窗口。
- 橙色：缺少必要铺垫或强化。
- 红色：已经逾期或被后续情节破坏。
- 灰色：作者批准废弃。

告警依据同时包含章节窗口和回收条件，不得通过机械回收消除告警。

### 7.7 核心 Skill 输出

- 关系变化提案。
- 伏笔新增、推进、回收、延期、改线或废弃提案。
- 当前可用的关系冲突与爽点。
- 缺失铺垫清单。
- 到期预警和风险说明。
- 可提交事件账本的结构化变更。

### 7.8 强制校验

- 关系转变是否有足够前置事件。
- 行为是否符合双方认知、利益和能力。
- 核心关系是否推动剧情或人物弧光。
- 工具关系是否越权占用主线资源。
- 伏笔是否有明确答案和回收条件。
- 回收是否对应早期证据。
- 误导是否公平，是否利用叙述漏洞欺骗读者。
- 短、中、长线伏笔数量是否失控。
- 章节钩子是否过度重复。
- 修改是否破坏既有关系和伏笔链条。

## 8. 八个创作流程 Skill

### 8.1 通用写作规范 Skill

作为独立模块和全流程强制规则，管理叙事视角、语言风格、节奏、信息密度、平台规范、移动阅读体验和 AI 腔检测。输入为作品定位、读者、文风样本、平台要求与禁忌；输出为可执行规则、正反例和检查报告。

强制检查：视角漂移、风格突变、比例失衡、禁用表达、无效重复、模板句式和平台违规。

### 8.2 选题 Skill

将模糊创意转化为 3–5 个候选方案，输出一句话卖点、核心冲突、读者承诺、题材融合、差异化风险、扩展潜力和推荐理由。

强制检查：卖点清晰度、主角欲望、题材协同性、前三章兑现能力、长篇空间与禁忌。

### 8.3 世界观 Skill

输出时空、社会、组织、资源、能力、阶层、利益分配、世界秘密和认知层级，并生成可写入设定字典的条目。

强制检查：设定对剧情的作用、能力代价与边界、资源与权力自洽性、普通人生存逻辑、主角特权和规则矛盾。

### 8.4 人物 Skill

输出人物欲望、恐惧、秘密、底线、外在目标、内在需求、能力限制、行为模式、人物弧光、语言动作特征、初始状态和关系提案。

强制检查：行动驱动力、优缺点后果、不可替代性、反派合理性、人物同质化、能力合规和弧光铺垫。

### 8.5 大纲 Skill

输出全书方向、当前卷目标、主支线、人物线、阶段高潮、章级目标、冲突、爽点、转折、钩子、伏笔窗口和弹性节点。

强制检查：章节是否改变局势、主线推进、爽点铺垫、高潮因果、支线价值、关系与伏笔预排、结构重复和卷承诺兑现。

### 8.6 正文 Skill

输出章节正文、摘要、新事实候选、人物与关系变化、物品和任务变化、伏笔与钩子变化、大纲偏差及待决事项。

强制检查：前章衔接、人物状态、知情范围、能力与物品一致性、本章目标、冲突结果、场景表达、结尾钩子、变化清单一致性和 S/A 级设定保护。

### 8.7 润色 Skill

在不擅自改变事实、因果和人物动机的前提下输出润色正文、重要修改对照、逻辑问题和跨 Skill 修改提案。

强制检查：事实与因果变化、伏笔误删、认知泄漏、人物语言同质化、辞藻堆积、模板句式及未经批准的剧情修改。

### 8.8 复盘 Skill

按章节、阶段和整卷输出质量报告、节奏与爽点统计、关系推进、人物弧光、伏笔完成率、重复素材、风格漂移、大纲偏差和后续行动。

复盘只生成提案，不直接修改正式数据。

强制检查：读者承诺兑现、人物主动性、关系铺垫、伏笔公平性、剧情线停滞、素材重复和建议可执行性。

### 8.9 流程门禁与回退

默认流程为：

`通用规范 → 选题 → 世界观 → 人物 → 大纲 → 正文 → 润色 → 复盘`

正文或复盘可以提出回退人物、大纲或世界观的变更提案。任何回退先执行影响分析，已批准数据不得自动覆盖。

## 9. 可视化后台

### 9.1 创作驾驶舱

展示当前卷章、继续创作入口、今日待办、三级告警、到期伏笔、待补关系铺垫、待确认提案、最近版本和卷级健康指标。

### 9.2 创作流程中心

以阶段卡片展示七个顺序阶段，通用规范固定在顶部。每个阶段展示状态、批准版本、输入完整度、问题、运行记录和可进入的下一阶段。

### 9.3 章节创作工作台

- 左侧：卷纲、章纲、前后章节和剧情线。
- 中间：正文编辑器和 AI 共创区域。
- 右侧：本章记忆、人物、关系、伏笔、禁忌和告警。

支持整章、场景和局部生成；作者可只批准正文而暂存某项新设定提案。

### 9.4 创作记忆中心

提供设定字典、剧情进度、人物状态、伏笔台账、已用素材和全局禁忌六个入口。支持按卷、章、人物、剧情线和状态筛选，并查看来源、历史版本、关联对象和影响范围。

### 9.5 人物与关系图谱

支持四级筛选、双向关系、公开与真实状态切换、章节历史回放、冲突爽点标记和关系转变因果链。

### 9.6 伏笔看板

按待埋设、已埋设、待强化、待回收、已回收和风险项分列；支持分级视图、章节时间轴、卷完成率和终极真相依赖图。

### 9.7 版本与影响中心

展示修改前后、修改原因、受影响对象、处理建议和作者决定。恢复历史版本同样生成新事件，不删除历史。

### 9.8 模型设置

允许按选题、规划、正文、校验和复盘配置首选及备用模型。展示预计成本、上下文使用量和失败切换状态，但默认隐藏复杂参数。

### 9.9 交互原则

- 默认展示结论，依据可展开。
- 阻断问题必须指出冲突事实和来源。
- AI 修改提供差异对比。
- 批准、拒绝、暂存和破例必须清晰区分。
- 编辑内容不得因模型或后台失败而丢失。
- 高风险操作可撤回，但撤回保留历史。

## 10. 模型适配与 Skill 运行协议

### 10.1 模型适配器

适配器统一提供：

- 文本生成。
- 结构化生成。
- 流式输出。
- 能力和上下文长度声明。
- 成本估算。
- 超时、重试和取消。
- 安全的错误映射。

Skill 只声明任务能力，不引用具体模型名称。MVP 至少实现两个模型适配器。

MVP 的两个协议族为：

- OpenAI 兼容协议：覆盖官方服务及提供兼容接口的本地模型运行器。
- Anthropic 兼容协议：覆盖 Claude 系列服务。

其他供应商通过新增适配器接入，不修改 Skill 协议。

### 10.2 Skill 清单

每个 Skill 必须携带：

- 唯一编号、名称和语义版本。
- 适用阶段和允许调用者。
- 所需输入对象及最低版本。
- 输出 Schema。
- 允许提出的事件类型。
- 前置和后置校验清单。
- 失败、降级和人工接管策略。
- 标准样例、反例与契约测试。

### 10.3 权限边界

- Skill 不得直接操作数据库或覆盖文件。
- Skill 只可读取编排层提供的上下文。
- Skill 只可输出草稿、分析和变更提案。
- 正式入账由创作记忆核心执行。
- S/A 级设定变更必须显式确认，不可批量静默批准。

## 11. 非功能需求

### 11.1 容量与性能

- 单作品至少支持 50 章、30 万字。
- 至少支持 200 个人物、1,000 条关系记录。
- 至少支持 500 条伏笔及状态事件。
- 至少支持 10,000 条设定、素材和剧情事件。
- 本地列表、筛选和状态查询在标准验收设备上 2 秒内完成。
- 模型响应时间单独统计。

标准验收设备定义为：Windows 11、四核处理器、16 GB 内存、固态硬盘。性能测试使用固定的 50 章、30 万字基准作品；首次全文索引和备份恢复不计入 2 秒交互查询指标，另行记录耗时。

### 11.2 可靠性

- 正文、事件和状态更新采用原子事务。
- 模型失败不改变正式数据。
- 重试具备幂等性。
- 编辑器自动保存草稿。
- 每次正式批准后生成增量备份。
- 可由事件账本与快照重建状态。

### 11.3 隐私与密钥

- 正文和设定默认仅保存在本地。
- API 密钥保存在操作系统安全凭据中。
- 调用模型前可查看将发送的数据范围。
- 敏感作者备注和终极真相可标记为禁止发送。
- 导出包不包含密钥及敏感调用日志。

### 11.4 可观测性

记录 Skill 与版本、模型、耗时、使用的记忆版本、输入输出摘要、校验结果、作者决定及正式事件编号。完整日志用于追溯，默认界面仅展示必要信息。

## 12. 异常处理

- 模型超时：保留任务和草稿，可重试或切换模型。
- 上下文超限：按优先级缩减，并显示省略项。
- 设定冲突：指出冲突双方、来源和可选处理方案。
- 入账失败：整体回滚，不允许半成功。
- 影响分析规模过大：转为后台任务，作者可继续编辑草稿。
- Skill 版本不兼容：停止该 Skill，保留旧版本和迁移提示。
- 作者有意破例：保存理由、范围和期限，避免重复告警。
- 模型结构化输出错误：自动修复一次；仍失败则换模型或人工处理，不得入账。

## 13. 测试策略

### 13.1 单元测试

覆盖时间线、状态回放、关系分级、伏笔窗口、版本差异、影响范围、禁忌规则、素材相似度和幂等提交。

### 13.2 集成测试

覆盖完整闭环：

`任务创建 → 记忆组装 → 模型调用 → 输出校验 → 作者批准 → 事件入账 → 状态更新 → 快照生成`

### 13.3 一致性测试集

至少包含：

- 死亡人物无解释出现。
- 使用尚未获得的能力。
- 同一物品同时出现在两处。
- 角色提前知道秘密。
- 伤势无条件痊愈。
- 敌对关系无铺垫转为忠诚。
- 伏笔答案与早期证据冲突。
- 润色误删关键证据。
- 普通章节试图修改 S/A 级设定。

### 13.4 恢复测试

覆盖模型中断、应用退出、数据库写入失败、重复批准、备份恢复和由事件账本重建全部状态。

## 14. MVP 验收标准

1. 从选题开始走完一卷 30–50 章的完整流程。
2. 六类创作记忆随章节更新并可追溯。
3. S/A 级设定无法未经确认修改。
4. 产品预置的确定性硬冲突测试全部被阻断。
5. 人物状态、物品和知情范围可按章节回放。
6. 关系跳变能够被识别并指出缺失铺垫。
7. 短线伏笔按窗口预警，中线伏笔生成卷末完成率。
8. 正文和状态更新不存在半成功状态。
9. 项目导出后可在新环境完整恢复。
10. 至少两个模型适配器通过统一契约测试。
11. 任一正式变更均可查看来源、原因、版本和批准记录。

“全部被阻断”只适用于产品内预先定义、结果确定的硬冲突测试集，不代表对任意自然语言矛盾达到 100% 识别率。开放文本检测使用独立、经人工标注的样本集验收：阻断级冲突精确率不低于 90%，召回率不低于 85%；同时单独记录作者确认的误报和漏报。样本集不得直接出现在生产提示词或规则样例中。

## 15. 推荐技术路线

### 15.1 MVP 技术形态

- 桌面外壳：Electron。
- 前端：React + TypeScript。
- 本地业务服务：Node.js + TypeScript。
- 状态数据库：SQLite。
- 数据校验：结构化 Schema。
- 检索：结构化查询与全文检索为主，语义检索为补充。
- 正文及快照：Markdown/YAML。
- 密钥：操作系统安全凭据。
- 工程组织：界面、创作核心、Skill 运行时、模型适配器和数据协议分包。

正式实施前需要通过一个小型技术验证确认桌面打包、数据库驱动、系统密钥存储和目标模型 SDK 的兼容性。若 Electron 的资源占用在目标设备上不达标，可在保持 TypeScript 核心包不变的前提下评估更轻量的桌面外壳。

### 15.2 核心代码边界

```text
AI 智能小说家
├─ 桌面应用与可视化后台
├─ 创作流程编排器
├─ Skill 运行时
│  ├─ 人物关系与伏笔管理
│  └─ 八个创作流程 Skill
├─ 创作记忆核心
│  ├─ 事件账本
│  ├─ 状态计算
│  ├─ 版本与影响分析
│  ├─ 上下文组装
│  └─ 一致性校验
├─ 多模型适配层
└─ 导入、导出与备份
```

## 16. 实施阶段与里程碑

### M0：协议与工程底座，预计 2 周

- 数据对象、事件和状态机。
- Skill 与模型适配协议。
- 本地应用、SQLite、迁移和测试框架。

退出标准：事件幂等、状态可回放、数据可追溯。

### M1：创作记忆核心，预计 3–4 周

- 六类记忆。
- 事件入账、状态回放、版本和影响分析。
- 上下文组装、校验、快照和备份。

退出标准：可还原任意章节结束时的测试状态。

### M2：关系与伏笔核心 Skill，预计 2–3 周

- 四级关系、双向关系、演变台账。
- 冲突、爽点和铺垫绑定。
- 伏笔生命周期、预警和卷复盘。

退出标准：识别预置关系跳变和伏笔风险样本。

### M3：八个流程 Skill，预计 4–5 周

- 第一批：通用规范、世界观、人物、大纲、正文。
- 第二批：选题、润色、复盘。

退出标准：从批准章纲生成正文，并输出可校验的变化清单。

### M4：可视化后台，预计 3–4 周

与 M2、M3 部分并行，交付驾驶舱、流程中心、章节工作台、记忆中心、关系图谱、伏笔看板、版本中心和模型设置。

退出标准：作者无需直接编辑数据库或结构化文件即可走完流程。

### M5：一卷实战与质量加固，预计 3–4 周

以真实 30–50 章样书进行端到端验证，处理模型差异、上下文遗漏、误报漏报、审批负担、性能、备份恢复和 Skill 规则迭代。

退出标准：通过第 14 节 MVP 验收标准。

### 16.1 周期估算

- 4–6 人团队：17–22 周。
- 2–3 人团队：6–8 个月。
- 单人开发：建议缩减首版范围，预计 9–12 个月。

排期是产品级估算，任务级计划应在本设计书面确认后另行生成。

## 17. 优先级

### P0

- 六类创作记忆。
- 事件账本、版本和影响分析。
- 人物状态连续性。
- 关系与伏笔管理。
- 通用规范、大纲、正文、润色和复盘主链路。
- 至少两个模型适配器。
- 备份与恢复。

### P1

- 选题、世界观和人物引导向导的完整体验。
- 关系图谱和伏笔时间轴。
- 素材相似度检测。
- 成本统计、备用模型切换和低风险批量审批。

### P2

- 语音输入、移动端、自动发布。
- 模板或 Skill 市场。
- 云同步和多人协作。

说明：八个流程 Skill 均属于 MVP 功能范围。P1 表示相应模块的高级引导和可视化体验可在核心协议与基础流程可用后补齐，不表示移除该 Skill。

## 18. 团队建议

- 产品负责人兼网络小说创作专家：规则、样例与验收。
- 全栈工程师：桌面端、业务服务与本地数据。
- AI 工程师：Skill、模型适配、上下文与校验。
- 交互设计支持：章节工作台和复杂信息展示。
- 测试支持：一致性、契约和恢复测试集。

创作质量不能仅由开发人员或模型自评，必须包含作者人工评分。

## 19. 主要风险与对策

| 风险 | 对策 |
|---|---|
| 模型编造或遗漏事实 | 结构化事实优先；模型只提交提案；入账前校验 |
| 上下文持续膨胀 | 最小上下文包；分类预算；可见的省略记录 |
| 审批负担过重 | 风险分级；低风险批量批准；S/A 级禁止静默审批 |
| 规则过多限制创作 | 阻断、警告、建议分级；允许有理由破例 |
| 早期设定修改产生连锁问题 | 修改前影响分析；待复核队列；章节版本回放 |
| 模型格式差异 | 统一 Schema；自动修复；适配器契约测试 |
| 数据结构演进 | 事件与 Schema 版本化；迁移与回放测试 |
| 创作质量难量化 | 自动指标、作者评分和真实章节评测集并行 |

## 20. SaaS 扩展路线

商业化阶段新增：

- 用户、作品空间和多租户隔离。
- 云数据库、对象存储与任务队列。
- 登录、订阅、计费、额度、限流和成本路由。
- 团队权限、批注、协作审批和审计日志。
- 云备份、跨设备同步、模板与 Skill 市场。

迁移原则：保留 Skill、事件和模型适配协议，替换本地基础设施，不重写创作业务规则。
